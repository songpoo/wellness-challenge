# 45Days Challenge High-Context Tracking Coach — PRD & User Stories (v4.1)

노바(Novah)님이 설계하신 **'45일 챌린지 고맥락 트래킹 코치 봇(v4.1)'**의 시스템 인스트럭션을 바탕으로, 이를 실제 서비스로 구현하기 위한 **PRD(제품 요구사항 문서)**와 **User Story**를 정리한 문서입니다.

이 문서는 'Self-Architecture'라는 철학을 실무적인 언어로 치환하여, 설계자로서의 관점을 단단하게 유지하도록 구성했습니다.

## 📄 PRD: 45Days Challenge High-Context Tracking Coach

### 1. 제품 개요 (Product Overview)

- **제품명**: 🏋🏻‍♂️ 45Days Challenge Coach (v4.1)
- **슬로건**: "기록의 번거로움은 기술에게, 삶의 주도권은 당신에게."
- **핵심 가치**: **Self-Architecture**. 사용자가 복잡한 건강 데이터를 직접 관리하는 스트레스에서 벗어나, AI가 설계한 시스템 안에서 실질적인 안도감과 성취감을 느끼게 함.
- **AI 분류**: **AI Native** — 멀티모달 분석·점수 산출·코치 코멘트가 핵심. AI 빠지면 단순 수기 트래커. 상세 스펙은 [`docs/AI-PRODUCT-SPEC.md`](AI-PRODUCT-SPEC.md) 참조.
- **데이터 아키텍처**: **Supabase Postgres가 주 DB**, Notion 연동은 *개인 사용자가 자기 워크스페이스로 가져가는 export 옵션*. 다중 사용자 환경에서 PO 분석·집계는 모두 Supabase 기반. 상세는 [`docs/DB-DESIGN.md`](DB-DESIGN.md).

### 2. 타겟 유저 (Target Audience)

1. **System Seekers**: 의지력보다 시스템의 힘을 믿고, 데이터 기반의 성장을 원하는 직장인 및 전문직.
2. **Low-Friction Trackers**: 정교한 기록을 원하지만 매번 칼로리를 검색하고 입력하는 과정에 피로감을 느끼는 유저.
3. **Context-Driven Achievers**: 단순한 수치를 넘어 자신의 행동이 목표에 어떻게 기여하는지 고맥락(High-Context) 피드백을 원하는 유저.

### 3. 핵심 기능 (Functional Requirements)

#### 3.1. 지능형 온보딩 (Smart Onboarding)

- **유연한 입력 파싱**: 숫자만 입력해도 단위(kg, 시간)를 자동 인식하고, 다양한 날짜 형식을 지원함.
- **목표-루틴 정렬(Alignment)**: 사용자의 3대 목표를 먼저 확정한 후, 이에 최적화된 Daily Check 루틴을 자동 생성함.
- **시나리오 대응**: 시작일(과거/오늘/미래)에 따른 맞춤형 가이드 제공.

#### 3.2. 멀티모달 고맥락 분석 (Multi-modal Analysis)

- **Vision 인식**: 식단, 체중계, 운동 기구 사진을 분석하여 영양소 및 운동 종류를 추론함.
- **NLP 통합**: 텍스트와 사진 데이터를 결합하여 칼로리 밸런스와 단백질 섭취량을 정교하게 계산함.
- **결측치 처리**: 정보 부족 시 기본값(기초대사량 등)을 적용하여 분석의 연속성을 유지함.

#### 3.3. 듀얼 출력 시스템 (Dual Output System)

- **#공식용 (Human-Readable)**: 마크다운 기반의 시각적 리포트와 코치 코멘트 제공.
- **#노션용 (Machine-Readable)**: 외부 DB 연동을 위한 순수 JSON 출력(설명 문구 배제).

#### 3.4. 히스토리 기반 통계 (Historical Insights)

- **맥락 유지**: 세션 내 과거 기록을 기억하고 특정 날짜나 기간의 데이터를 조회 및 요약함.

### 4. 비기능적 요구사항 (Non-Functional Requirements)

- **정확성**: 사진 분석 오차 범위 ±10% 이내 유지 (추세 파악 중심).
- **신속성**: 입력 후 5초 이내에 분석 리포트 생성 시작.
- **톤앤매너**: '지적인 다정함'을 유지하며 비난 없는 건설적 피드백 제공.

## 👥 User Stories

설계자(노바)와 사용자 사이의 접점을 구체적인 시나리오로 정의합니다.

### 1. 온보딩 및 설정

- **As a** 챌린지 입문자,
- **I want to** 내 체중과 시작 날짜를 자유로운 형식(예: "72", "11월 8일")으로 입력하고 싶어,
- **So that** 초기 설정 단계에서 느끼는 피로감을 최소화하고 즉시 시스템에 진입하고 싶기 때문이야.

### 2. 일일 트래킹 (식단 및 운동)

- **As a** 바쁜 직장인 유저,
- **I want to** 점심 식사 사진 한 장과 "오늘 30분 달림"이라는 짧은 텍스트만 던져주고 싶어,
- **So that** AI가 알아서 칼로리 밸런스를 계산하고 내 목표 대비 잘하고 있는지 알려주길 원하기 때문이야.

### 3. 데이터 자산화 (노션 연동)

- **As a** 기록에 진심인 유저,
- **I want to** 대화 내용 중 데이터만 따로 JSON 형태로 뽑아내고 싶어,
- **So that** 내 개인 노션 워크스페이스에 깔끔하게 아카이빙하여 장기적인 변화를 추적하고 싶기 때문이야.

### 4. 동기 부여 및 피드백

- **As a** 의지력이 약해진 챌린저,
- **I want to** 단순히 "잘했다"는 칭찬보다 "단백질이 10g 부족하니 내일은 계란 하나를 더 드세요" 같은 구체적인 제안을 받고 싶어,
- **So that** 내가 시스템 안에서 안전하게 보호받고 관리되고 있다는 '안도감'을 느끼고 싶기 때문이야.

### 5. 과거 기록 조회

- **As a** 성찰이 필요한 주말의 나,
- **I want to** "이번 주 평균 행동 점수가 어땠어?"라고 물어보고 싶어,
- **So that** 지난 일주일의 시스템 작동 여부를 확인하고 다음 주의 전략을 수정하고 싶기 때문이야.
